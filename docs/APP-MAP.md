# Fernly app map

Mapped on 2 Nov 2026 from `docs/PRODUCT.md`, the OpenAPI document at `http://localhost:8100/openapi.json`, and `web/src/pages` plus `web/src/components`. Then every route was opened at `http://localhost:5173`.

Signed-out first. Then signed in as `ava@fernly.test` (the first customer in `.env.example`) to open the cart, checkout, and orders. One Aloe Vera was added so the cart line and the checkout form could be seen, then removed. No order was placed. After that, Sign out returned the header to Sign in and sent `/cart` to `/login?next=/cart`.

The browser calls `http://localhost:5173/api/...` (the dev proxy). Those are the same paths as the OpenAPI server at `http://localhost:8100`. When `localStorage` holds `fernly_token`, `apiFetch` sends `Authorization: Bearer` on every call. Saved plants (the heart on a card) use `localStorage` key `fernly_saved` and no API.

`Layout` wraps every route: skip link, header, `<main id="main">`, footer. A full load with a saved token calls `GET /api/auth/me` (this dev build issued it twice, from React `StrictMode`). After the customer is known, `GET /api/cart` fills the header badge. The badge is the cart's `itemCount`, and it is omitted when that count is 0.

States that flashed past too quickly to read, or that need a failed server, are marked **from code**. Everything else was on screen.

## API

"Needs sign-in?" is the OpenAPI security rule (`bearer` on the operation). It is not "does the browser attach a token": a saved token is attached to public calls too.

| Method and path | Used by which page | Needs sign-in? |
| --- | --- | --- |
| `GET /api/health` | No page. | No |
| `POST /api/admin/reset` | No page. | No |
| `GET /api/plants` | Browse. Plant also calls it with `pageSize=48` to name "Likes the same light" links. | No |
| `GET /api/plants/{plantId}` | Plant | No |
| `POST /api/auth/register` | Register | No |
| `POST /api/auth/login` | Login | No |
| `GET /api/auth/me` | Layout, on load when a token is saved. | Yes |
| `GET /api/cart` | Layout (badge), Cart, Checkout. The query is enabled only when a customer is signed in. | Yes |
| `POST /api/cart/lines` | Plant (Add to cart) | Yes |
| `PATCH /api/cart/lines/{lineId}` | Cart (quantity) | Yes |
| `DELETE /api/cart/lines/{lineId}` | Cart (Remove) | Yes |
| `POST /api/orders` | Checkout (Place order) | Yes |
| `GET /api/orders` | Orders. The query also runs while signed out; that request returned 401 and the page redirected to login. | Yes |
| `GET /api/orders/{orderId}` | Order. The query also runs while signed out, before the redirect to login. | Yes |
